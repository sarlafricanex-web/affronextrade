🟢 1. Execution automatique
Aucun script preinstall ou postinstall. Le script prepublishOnly lance juste tsc (compilation TypeScript). RAS.
🟢 2. Code suspect
Aucune obfuscation, pas d'eval(), exec(), Function() ou atob(). Le code source est court, lisible et transparent (un seul fichier src/index.ts).
🟠 3. Reseau
Toutes les requetes vont vers https://21st.dev/api/mcp (endpoint officiel). Mais l'URL peut etre surchargee via la variable MCP_URL_21ST, ce qui redirigerait la cle API et toutes les donnees vers un serveur tiers.
🟢 4. Vol de donnees
Aucun acces au systeme de fichiers, aux cookies, aux profils navigateur, aux cles SSH ou aux wallets. Pas de lecture de donnees locales.
🟢 5. Secrets exposes
Aucune cle API, token ou mot de passe en dur dans le code. Les cles sont lues via variables d'environnement. Le .gitignore est present.
🟢 6. Binaires sans source
Un seul fichier binaire : assets/logo.png (logo du projet). Aucun .exe, .dll, .so ou archive suspecte.
🟢 7. Dependances
Zero dependance de production. Seulement 3 devDependencies standard : @types/node, shx, typescript. Pas de typosquatting.
🟢 8. GitHub Actions
Workflow bien securise : pas de pull_request_target, actions epinglees par SHA, npm Trusted Publishing (OIDC), verification d'integrite du tarball, --ignore-scripts a l'install.
🟠 9. Reputation globale
Organisation creee en fevrier 2025, 582 followers, 15 repos publics, 6 404 stars. Communaute active. Le repo est un proxy : il redirige tout le trafic MCP vers les serveurs de 21st.dev. Vos prompts et le code genere transitent par leur API.

Tableau des risques

Moyen
src/index.ts - fetch POST vers 21st.dev/api/mcp
Proxy integral : chaque message JSON-RPC (vos prompts, arguments d'outils, code) est transmis tel quel au serveur distant 21st.dev. C'est le fonctionnement normal d'un MCP distant, mais cela signifie que 21st.dev recoit tout le contenu de vos interactions.
Moyen
src/index.ts - variable MCP_URL_21ST
Endpoint surchargeable : la variable d'environnement MCP_URL_21ST permet de rediriger tout le trafic (cle API incluse) vers un serveur arbitraire. Verifier qu'elle n'est pas definie dans votre environnement.
Moyen
src/index.ts - lecture de API_KEY
Variable generique : le code lit aussi la variable API_KEY (sans prefixe). Si une autre application definit cette variable, sa cle pourrait etre envoyee a 21st.dev par erreur.
Faible
Dockerfile
Container en root : le Dockerfile n'ajoute pas d'utilisateur non-root. Risque faible car l'usage principal est via npx, pas Docker.
Faible
src/index.ts - reponses du serveur
Reponses non validees : les reponses du serveur distant sont relayees sans verification. Un serveur compromis pourrait injecter du contenu manipule dans les reponses de l'agent.

Peut-on cloner et utiliser ce repo ?

Oui, avec precautions. Le code est propre, court et transparent. Aucun comportement malveillant detecte. Mais c'est un proxy : vos donnees transitent par les serveurs de 21st.dev. Cela merite attention.

  1. Utilisez la methode d'installation officielle : npx @21st-dev/cli@latest init (recommande par le repo lui-meme).
  2. Creez une cle API dediee sur 21st.dev/mcp. Ne reutilisez pas une cle d'un autre service.
  3. Verifiez vos variables d'environnement : assurez-vous que MCP_URL_21ST et API_KEY ne sont pas definies ailleurs.
  4. Passez la cle par variable d'environnement, jamais en argument de ligne de commande.
  5. Sachez que vos prompts et le code genere transitent par les serveurs de 21st.dev. Evitez de partager des donnees sensibles via cet outil.
